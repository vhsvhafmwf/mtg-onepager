# 議事録 → data.json の抽出ルール

見本: `assets/example.data.json`（架空の学生団体の幹部MTG）。迷ったらこの形に合わせる。

## スキーマ

```jsonc
{
  "org": "みなと学生祭 実行委員会",                  // 団体名
  "kind": "幹部会議キャッチアップ",                  // 見出し上の小見出し（会議の種類）。省略時「会議キャッチアップ」
  "title": "第12回 幹部MTG",                        // 「まとめ」は自動で付く
  "date": "2026年10月7日（水）",
  "place": "オンライン",
  "source": "Notion「MTG議事録 / 第12回幹部MTG」（2026-10-09 時点）",  // どこから読んだか＋読んだ日
  "note": "議事録の決定事項欄は空欄。本文とコメントから整理",          // 読み方の但し書き。無ければ ""
  "unit": "局",                                      // 部署の呼び方（「各局の進捗」の「局」）。省略時「部署」
  "teams": {                                         // 凡例の順に並ぶ。color は #RRGGBB のビビッド色
    "kikaku": { "name": "企画局", "color": "#2F6BFF" }
  },
  "decisions": [                                     // 議題として扱われ、結論が出た／出なかったもの
    { "status": "done", "team": "kikaku", "q": "議題（短く）", "a": "結論（何をどうするか）" },
    { "status": "open", "team": "daihyo", "q": "議題", "a": "何が割れているか／何待ちか" }
  ],
  "pending": [                                       // 依頼・質問で返事がまだのもの（すべて未決）
    { "team": "shogai", "from": "広報", "to": "渉外局", "text": "何を聞いている／頼んでいるか" }
  ],
  "progress": [                                      // 部署ごとの進捗報告。items は 見出し＋本文
    { "team": "koho", "items": [ { "h": "パンフレット", "t": "仮原稿は 11/1 締切" } ] }
  ],
  "schedule": [                                      // 会議後の近い予定。最大4件、1件だけ now:true
    { "date": "10/9", "dow": "金", "text": "22:00 企画局 MTG", "team": "kikaku", "now": true }
  ]
}
```

## 部署（teams）と色

- 部署ごとに次の系統から色を割り当てる（この順で使うと見分けやすい）:
  青 #2F6BFF ／ ピンク #FF2E7E ／ 紫 #8B3DFF ／ 黄 #FFB800 ／ 緑 #00B39B ／ 水色 #00A3FF
- 状態色のオレンジ #FF5A1F に近い色は使わない（決定・未決のチェックと紛れる）。
- 全体宛て・担当未定の受け皿として `zentai`（全体）を1つ置くとよい。
- 依頼（pending）の team は**依頼先**の部署。担当未定・全体宛ては `zentai`。

## 分類の判定（ここが品質を決める）

| 議事録の書かれ方 | 入れ先 |
|---|---|
| 「〜でOK」「〜に決定」「承認」、担当者と行動が決まった | decisions / done |
| 方針だけ決まった（「もう一回面談しましょう」） | decisions / done（a に方針をそのまま） |
| 議論したが意見が割れた・結論なし | decisions / open（a に「何と何で割れているか」） |
| 「to ○○」の依頼・質問で、返事が議事録やコメントに無い | pending |
| 「担当誰？」で決まっていない | pending（to: "担当未定"） |
| 議題名だけあって中身が空 | pending（to: "全体"、text に「本文は空欄」と事実を書く） |
| 各部署の報告（やった・やる・予定） | progress |
| 日付つきの近い予定・締切 | schedule（progress と重複してよい） |

- **コメントを必ず読む**: Notion はハイライトにコメントが付き、そこで「OK!」と決まっていることが多い。本文だけだと決定を取りこぼす。
- **捏造しない**: 結論が書かれていない議題を done にしない。数字・日付・人名は原文にあるものだけ。
- **出席者名簿は載せない**。本文の人名は、担当や意見の帰属に必要なときだけ残す。
- **note**: 決定事項欄が空・書記なしなど、読み取りに推測が入ったときは必ず書く。

## 書き方

- q は 20〜30字、a は 40字前後、pending.text は 45字以内、progress の t は 40字以内。長いと自動縮小（最小 0.82 倍）でも収まらず止まる。
- progress の h は 2〜9字の名詞（「新歓インスタ」「note」「たこ焼きパーティ」）。h は自分で付けてよいが、t は原文の事実だけ。
- 1部署の progress は3件まで。多い回は重要な3件に絞り、残りは捨てる（報告で「省いた」と言う）。
- schedule は会議日より後の予定から、近い順に4件。今日以降で最も近い1件に now:true。
  過去の回をまとめていて今日以降の予定が無いときは、会議日の直後の1件を now:true にし、note に「予定は会議日基準」と書く。
- 曜日 dow は日付から計算して入れる（原文に無くても可）。
