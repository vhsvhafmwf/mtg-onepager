# mtg-onepager — 議事録を1枚の画像にする

議事録 → `data.json`（決定／未決／進捗／予定に分類）→ `scripts/render.mjs` で JPEG。
デザインは固定（カンバン型。決定=白カード＋塗りチェック、未決=部署色カード＋中抜きチェック、部署=ビビッド色の凡例と左帯）。見本の完成形は `assets/example.data.json` を描いたもの。

以下の `<skill-dir>` は、このスキルのディレクトリ（この SKILL.md がある場所）の絶対パスに読み替える。

## 手順

### 0. 初回だけ: 描画環境を入れる
`<skill-dir>/scripts/node_modules` が無ければ、ユーザーに次を実行してよいか聞いてから入れる（Node.js 18 以上が要る。Chromium を約150MB ダウンロードする）。
```bash
npm install --prefix "<skill-dir>/scripts"
npx --prefix "<skill-dir>/scripts" playwright install chromium
```

### 1. 議事録を読む（入力の形で分ける）
- **テキスト・ファイル・文字起こし**: そのまま読む。発話ログなら、議題ごとに結論を拾ってから分類する。
- **Notion などの URL**: 使える手段で本文を読む（Notion MCP、ブラウザ操作ツール、WebFetch の順に試す）。どれでも読めなければ、ページの書き出し（Markdown）か本文の貼り付けをユーザーに頼む。
  - ブラウザで読むときは、**トグルをすべて開いてから**本文を取る（閉じた中身は取れない）。Notion では最上位のトグルを1つクリックしてから `cmd+alt+t`（Windows は `ctrl+alt+t`）で入れ子も含めて全部開く。
  - **コメントを必ず読む**。決定はコメントに「OK!」「〜にします」で書かれていることが多い。どの文に付いたコメントか分からないときは内容から推定し、`note` に「コメントの対応箇所は推定」と書く。
  - 「今週の定例」のように回が指定されていなければ、日付が今日に最も近い過去の該当会議を選び、どれを選んだかを報告で言う。
  - 添付ファイルのダウンロードが要るものは、開く前に聞く。
- 議事録の編集は一切しない（読むだけ）。

### 2. data.json を作る
[references/extraction.md](references/extraction.md) のスキーマと分類表に従う。要点:
- 決定（done）は「結論か担当が書かれているもの」だけ。割れた議論は open、返事待ちの依頼は pending。
- 進捗は 見出し(h)＋本文(t) の2段。本文は原文の事実だけ、見出しは自分で付けてよい。
- 出席者名簿は載せない。推測が入ったら `note` に書く。
- 共有される画像なので、個人の体調・メンタル・評価・合否（応募者の実名と ✅✘ など）は載せない。論点だけを中立に書く（例: 「副リーダー（仮）を立てるか」）。
- 置き場所: 作業中のプロジェクトがあればその `output/`、無ければ作業用の一時ディレクトリ。ファイル名は `YYYYMMDD_<会議名>_onepager.json`。

### 3. 書き出す
```bash
node "<skill-dir>/scripts/render.mjs" <data.json> <out.jpg>
```
- 成功すると `{"ok":true,...,"preview":"<out>.preview.jpg","fit":1,"webFonts":true,"decided":4,"open":7,...}` を出す。
  - `fit` < 1 は自動で文字を縮めた倍率。
  - `webFonts:false` は Google Fonts を取れず OS の日本語フォントで描いたという意味（オフライン等）。崩れていないか特に注意して見る。
- 止まったとき（exit 1）:
  - `データ検査で止めた` → 列挙された箇所を直して再実行。
  - `縮めても収まらない: colN +XXXpx` → その列の文を短くするか件数を絞る（col1=決定と予定、col2=未決、col3=進捗）。
  - `playwright が見つからない` / `Chromium を起動できない` → 手順0をやる。

### 4. 確認して渡す
- 出力の `preview`（1920×1080 の縮小版）を Read で開き、**目で見る**（はみ出し・重なり・部署の色の取り違え・文字化け）。
- 報告には次を書く: 出力パス／どの会議を読んだか／決定・未決・進捗の件数／`fit` の値／推測で埋めた点と省いた点（note に書いたもの、絞った進捗、開けなかった添付）。

## やらないこと
- Slack などへの投稿（頼まれたら、投稿前に確認する）。
- デザインの作り直し。変えたいと言われたら `assets/template.html` を直し、`assets/example.data.json` で描き直して見本と比べる。
